# 更新笔记地址逻辑说明

## 1. 作用

这个脚本的目标是：打开小红书个人主页，只从主页 DOM 里提取笔记官方地址，写回 CSV 的 `笔记官方地址` 列。

它不会走接口抓取，只依赖当前浏览器里已经打开的主页页面。

## 2. 输入输出

### 输入

- 源 CSV 必须包含这 3 列：
  - `笔记官方地址`
  - `笔记标题`
  - `主页链接`
- 浏览器必须已经能通过远程调试端口连接。
- 需要登录小红书账号，否则会进入扫码/验证页。

### 输出

- 主输出文件：
  - 默认写到 `地址已更新/原文件名.csv`
- 失败数据文件：
  - 默认写到 `地址已更新/原文件名_失败数据_时间戳.csv`

## 3. 处理主流程

1. 读取源 CSV。
2. 如果已经存在同名更新结果：
   - 先把已保存结果合并回源数据
   - 再从下往上找最后一个有效 `xsec_token`
   - 从这个 token 的下一行开始续跑
3. 按行处理：
   - 跳过空标题、空主页、`笔记暂未设置标题`
   - 如果 `skip_existing_xsec` 为真，且当前行已经有有效 `xsec_token`，则跳过
4. 每处理一条主页前，会先做一个基础间隔等待：
   - 默认基础值是 20 秒
   - 实际等待是 `基础值 ~ 基础值+20秒` 的随机值
5. 打开主页后：
   - 先检查是否进入登录/验证码页或频控页
   - 再等待业务 DOM 就绪
   - 然后只做一次标题匹配和链接提取
6. 提取成功就回写 `笔记官方地址`。
7. 处理完全部行后写回输出 CSV 和失败 CSV。

## 4. 恢复锚点

恢复逻辑不是看“输出文件有多少行”，而是看“最后一个有效 `xsec_token` 在哪一行”。

规则是：

- 从下往上扫描已保存结果
- 找到最后一个有效 `xsec_token`
- 从它的下一行继续处理
- 锚点前的失败行不回头补

这样可以避免这些情况：

- 前面有些笔记标题找不到地址，所以没有 token
- 中间夹着失败行
- 只要后面还有成功行，脚本不会误判“已经全部完成”

## 5. 页面状态处理

脚本把主页打开后可能出现的状态分成 3 类：

### 5.1 正常主页

满足业务 DOM 后，脚本会：

- 匹配 `笔记标题`
- 从 `a.title`、`a.cover`、`/user/profile/`、`/explore/` 链接里找带 `xsec_token` 的地址
- 转成标准形式：
  - `https://www.xiaohongshu.com/explore/{note_id}?xsec_token=...&xsec_source=pc_user`

### 5.2 登录 / 二次验证页

如果页面出现这些特征，就会进入静默挂起：

- `登录即可查看`
- `扫码验证身份`
- `请完成验证`
- `请通过验证`
- `手机号登录`
- `获取验证码`
- `请先登录`

挂起期间：

- 不再自动访问下一条
- 不再自动轮询页面
- 你需要人工扫码/完成验证
- 然后在 GUI 点“继续当前条”

默认最多等待 5 分钟，超时会记失败。

### 5.3 请求频繁 / 频控页

如果页面出现这些特征，也会静默挂起：

- `访问频繁`
- `操作频繁`
- `频次异常`
- `稍后再试`
- `安全验证`
- `二次校验`

处理方式和登录页一致：

- 不自动继续访问
- 不自动轮询
- 你手动恢复后点“继续当前条”

默认最多等待 5 分钟，超时会记失败。

## 6. “继续当前条”按钮

GUI 里有一个 `继续当前条` 按钮。

它的作用是：

- 让当前挂起的这一条继续往下执行
- 不会切到下一条
- 先等页面恢复到业务 DOM，再继续提取

这个按钮只对当前正在跑的更新任务有效。

## 7. 保存重试

写 CSV 时如果文件被 Excel 或其他程序占用：

- 脚本会提示你先关闭占用程序
- 然后在原文件路径上重试保存
- 最长重试 60 秒
- 如果你点了停止，保存重试也会尽快退出

## 8. 失败原因

常见失败原因有：

- `标题为空`
- `未找到标题匹配卡片`
- `找到标题匹配卡片但链接没有 xsec_token`
- `笔记卡片 DOM 未就绪`
- `登录/验证页面等待超时`
- `请求过于频繁页面等待超时`

## 9. 你实际跑批时的理解方式

可以把它理解成 4 步：

1. 找上次真正成功到哪里了
2. 继续处理剩下没 token 的行
3. 遇到登录/频控就停在当前条，等你人工处理
4. 保存时如果文件被占用，就原地重试
